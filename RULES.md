# Rules and judging

## Six rules for the day

1. **Teams of 4–5.** Mix design, code and domain knowledge. Teams of 3 merge into teams of 4.
2. **No pre-work.** No commits before 10:00 on 3 October. Libraries and frameworks are fine; the core of your solution is built today.
3. **Open source.** One public GitHub repo per team, with an open source licence (MIT or Apache-2.0). Everything built today is donated to the Comune di Milano.
4. **Public data only.** No personal data in any prototype, ever. Use invented or anonymised cases.
5. **A human decides.** Claude proposes; the citizen or the officer confirms. No automatic decisions about people.
6. **One submission per team**, by **16:00**, through the [submission form](SUBMISSION.md).

## How we judge

Each criterion is scored 0–5 by each juror. Two criteria count double. Maximum: **35 points**.

| Criterion | Weight | What we look for |
|---|---|---|
| **Day-one impact** | ×2 | Could the City use it tomorrow? Would it make a real difference to the people in the brief? |
| **AI at work** | ×2 | Does Claude do the work while the solution runs, not only while it was built? |
| **City data and sources** | ×1 | Does it use the City's data and knowledge in a meaningful way? |
| **Product and execution** | ×1 | Does it work? Do users get it on the first try? |
| **Pitch** | ×1 | What it is, for whom, and why it matters, in two minutes |

### Scoring guide

**Day-one impact**
- 5: ready, and high impact for a real group of citizens or staff
- 4: almost ready, high impact
- 3: ready, mild impact
- 2: almost ready, mild impact
- 1: not ready, or not impactful
- 0: off-brief

**AI at work**
- 5: Claude does the core job at runtime (understands, reasons over rules, decides what to ask, fills in, routes), with a human confirming where it matters, and the README explains it clearly
- 4: Claude does a real job at runtime, with some steps still hard-coded
- 3: Claude is used at runtime for one useful step (e.g. translation or summarising) around a mostly traditional app
- 2: AI at runtime is decorative: a chatbot bolted onto a static page
- 1: built with Claude, but nothing runs on Claude
- 0: no "Where Claude works" section in the README

**City data and sources**
- 5: several City sources combined in a meaningful way, sources cited
- 3: City data used, but superficially
- 1: no meaningful use of City data or knowledge

**Product and execution**
- 5: works end to end, polished, well scoped; users get it on the first try
- 3: the core works, with visible gaps
- 1: does not work

**Pitch**
- 5: clear story, working demo, the problem and the people are unmistakable
- 3: understandable, but the demo or the "why" is weak
- 1: the purpose is unclear

## Process

1. **16:00** submissions close.
2. Pitches: **2 minutes per team**, in submission order unless the staff says otherwise.
3. **17:00** the jury deliberates using these criteria.
4. **17:30** winners announced.
